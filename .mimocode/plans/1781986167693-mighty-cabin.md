# Phase 0 — Critical Fixes (P0)

## C-01: Fix refresh token bcrypt verification
**File:** `backend/src/auth/services/token.service.ts`

**Problem:** `isValidRefreshToken` (line 92) and `removeRefreshToken` (line 111) use `bcrypt.hash()` to re-hash the token, then compare with `.eq('token_hash', tokenHash)`. This never works because bcrypt uses random salts — hashing the same token twice produces different hashes.

**Fix:**
- `isValidRefreshToken`: Fetch all token hashes for the user from `refresh_tokens` where `user_id = userId AND expires_at > now()`. Iterate and use `bcrypt.compare(refreshToken, storedHash)` to find a match. Return `true` if found.
- `removeRefreshToken`: Same approach — fetch all hashes, find match with `bcrypt.compare()`, then delete by the row's `id`.
- Line 45 (`signRefreshToken`) is correct — it hashes for storage.

## C-06: Fix ActiveSessionPage to resolve exercise name, not UUID
**File:** `frontend/src/pages/ActiveSessionPage.tsx`

**Problem:** Line 367 sets `exerciseName: se.workoutExerciseId` — displays UUID instead of exercise name.

**Fix:** The session response includes `workoutExerciseId` (a reference to the workout_exercises table). Need to resolve to exercise name. Two-step approach:
1. After fetching the session, also fetch the workout exercises for that workout (using `workoutId` from session) which include exercise details.
2. Build a lookup map: `workoutExerciseId → exerciseName`.
3. Use the lookup when building `ExerciseState[]` instead of the raw UUID.

This requires the frontend to call the workout-exercises endpoint: `GET /workouts/:id/exercises` (which exists in the backend but the controller needs to be registered — see C-05).

Alternative simpler approach: modify the backend `getSessionById` to join `session_exercises` → `workout_exercises` → `exercises` and include exercise names in the response. But this is a larger backend change. **Recommended: frontend lookup approach.**

## C-07: Enable CORS in main.ts
**File:** `backend/src/main.ts`

**Problem:** No `app.enableCors()` — frontend on a different port will be blocked by CORS.

**Fix:** Add before `app.listen()`:
```ts
app.enableCors({
  origin: configService.get<string>('CORS_ORIGIN') || 'http://localhost:5173',
  credentials: true,
});
```
Also add `CORS_ORIGIN=http://localhost:5173` to `.env`.
