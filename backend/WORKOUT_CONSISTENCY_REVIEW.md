# Workout Consistency Metrics Review

This document reviews the `getWorkoutConsistency` function from a product/business perspective for each metric.

| Metric | Current Implementation | Mathematical Meaning | Valid Fitness Metric? | Influenced by Tests? | Recommended Production Implementation |
|--------|------------------------|----------------------|------------------------|----------------------|---------------------------------------|
| currentStreak | Calculates the number of consecutive days ending with the most recent workout day by: 1) getting all distinct workout dates, 2) sorting descending, 3) counting backwards from the most recent date until a break in consecutive days. | The number of consecutive days the user has worked out up to their most recent workout session (not necessarily today). | Yes, streak is a standard metric for tracking workout consistency and habit formation. | Yes, test expects streak=1 for single workout, 3 for three consecutive days, and 1 for gap case (most recent workout isolated). | Current implementation is acceptable. However, consider whether the streak should be considered broken if the user misses today (i.e., streak ending today). The current method counts from the most recent workout, which may be in the past. If the goal is to measure current streak including today, adjust to check from today backwards. |
| longestStreak | Calculates the maximum number of consecutive days in the user's entire workout history by: 1) getting all distinct workout dates, 2) sorting ascending, 3) iterating to find the longest sequence of consecutive days. | The longest streak of consecutive days the user has ever worked out in their lifetime. | Yes, longest streak is a meaningful metric for showcasing peak consistency and motivation. | Yes, test expects longestStreak=1 for single workout, 3 for three consecutive days, and 2 for gap case (streak of 2 then isolated workout). | Current implementation is acceptable and correct for lifetime longest streak. Consider adding a rolling window (e.g., longest streak in last year) if lifetime is less relevant for current motivation. |
| workoutsThisWeek | Counts workout sessions where `completed_at` is within the last 7 days (including today) relative to the current date. | The total number of workout sessions completed in the past 7 days. | Yes, weekly frequency is a standard metric for assessing recent workout volume and consistency. | Yes, test expects workoutsThisWeek=1 for single workout within week, 3 for three workouts within week, and 0 for workouts outside the week. | Current implementation is acceptable. The rolling 7-day window provides a consistent recent view. Consider aligning with calendar weeks (e.g., Sunday-Saturday) if business requirements specify, but rolling window is common for fitness apps. |
| workoutsThisMonth | Counts workout sessions where `completed_at` is within the last 30 days (including today) relative to the current date. | The total number of workout sessions completed in the past 30 days. | Yes, monthly frequency is a standard metric for assessing medium-term workout volume and consistency. | Yes, test expects workoutsThisMonth=1 for single workout within month, 3 for three workouts within month, and 3 for gap case (all workouts within month). | Current implementation is acceptable. The rolling 30-day window provides a consistent recent view. Consider aligning with calendar months if business requirements specify, but rolling window is common for fitness apps. |
| averageWorkoutsPerWeek | Calculated as `(workoutsThisWeek + workoutsThisMonth) / 2`. | This formula does not represent a clear or standard metric. It combines weekly and monthly counts in a way that lacks intuitive interpretation (e.g., 3 workouts/week + 12 workouts/month = 7.5, which is not an average per week over any defined period). | No, as currently implemented, it is not a valid fitness analytics metric due to its arbitrary combination of time windows without clear meaning. | Yes, test expects: (1+1)/2=1 for single workout, (3+3)/2=3 for three consecutive days, and (0+3)/2=1.5 for gap case, directly matching the formula. | Replace with a meaningful weekly average, such as: <br> - Average workouts per week over the last 4 weeks: `(workouts in last 28 days) / 4` <br> - Or, calculate workouts in last 28 days via a dedicated query and divide by 4. <br> This provides a stable, interpretable metric for weekly frequency. |
| adherencePercentage | Calculated as `(totalWorkoutDays * 14) / 3`. | This formula does not represent a standard percentage or clear adherence metric. It scales lifetime workout days by an arbitrary factor (14/3 ≈ 4.666), resulting in values that can exceed 100 and lack a clear bounded interpretation (e.g., 3 lifetime workout days yields 14.0, which is not a percentage). | No, as currently implemented, it is not a valid fitness analytics metric. It fails to represent a percentage, is not bounded, and the scaling factor lacks justification in fitness context. | Yes, test expects: (1*14)/3≈4.67 for single workout, (3*14)/3=14.0 for three workouts, and (3*14)/3=14.0 for gap case, directly matching the formula. | Replace with a standardized adherence metric, such as: <br> - Percentage of days worked out in the last 28 days: `(workouts in last 28 days / 28) * 100` <br> - Or, percentage of weeks with at least one workout in the last 4 weeks: `(number of weeks with ≥1 workout in last 28 days / 4) * 100` <br> These metrics are bounded between 0-100% and directly measure consistency against a time-bound goal. |
| totalWorkoutDays | Counts the number of distinct days on which the user has ever worked out (lifetime unique workout days). | The lifetime count of unique calendar days with at least one workout session. | Yes, lifetime total workout days is a valid metric for showing overall workout history breadth and long-term commitment. | Yes, test expects totalWorkoutDays=0 for no workouts, 1 for one workout (on unique day), and 3 for three workouts (each on unique day). Note: multiple workouts on same day count as one day. | Current implementation is acceptable for lifetime view. Consider adding a complementary rolling window metric (e.g., workout days in last year) if recent activity is more relevant for current goals, but lifetime remains valuable for milestones. |

## Summary of Recommendations
- **currentStreak, longestStreak, workoutsThisWeek, workoutsThisMonth, totalWorkoutDays**: Current implementations are fundamentally sound and align with common fitness metrics. Minor adjustments (e.g., streak definition relative to today) may be considered based on product goals but are not required.
- **averageWorkoutsPerWeek**: The current formula is arbitrary and meaningless. Replace with a proper weekly average (e.g., workouts in last 28 days divided by 4).
- **adherencePercentage**: The current formula is nonsensical as a metric. Replace with a bounded percentage metric reflecting recent consistency (e.g., % of days worked out in last 28 days).

Note: These recommendations are for production implementation. The existing code should not be modified per the user's request, but this analysis guides future improvements.
